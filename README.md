# Промт «Пиши по-человечески»

Навык ставит одна команда, остальные способы — в разделе [«Как подключить»](#как-подключить):

```bash
npx skills add anton-vinogradov/human-writing -g
```

## Что не так

Claude пишет рабочие тексты так, что их трудно читать:
- в пункте плана вместо того, что появится, — имена классов, коммиты и тесты в скобках внутри скобок;
- в документе — история: «сначала делали так, потом выяснилось, теперь так»;
- вместо последствия — абстракция: «повышает надёжность», «обеспечивает гарантии»;
- канцелярит и калька с английского: «имплементирует подписку», «адресовать замечания»;
- где во входных данных нет факта, Claude вставляет правдоподобную догадку, и читатель принимает её за факт.

Такой текст приходится переписывать руками или переспрашивать автора.

## Что предлагается

Промт в файле [`prompt.md`](prompt.md), около 750 слов. Если подключить промт постоянным правилом, Claude применяет его ко всем рабочим текстам без напоминаний.
Тот же промт лежит в [`skills/human-writing/SKILL.md`](skills/human-writing/SKILL.md) навыком (skill). Навык Claude загружает сам, когда видит подходящую задачу.

Что он требует от Claude:
- первая фраза несёт главную мысль;
- каждая часть текста отвечает на один вопрос;
- факты берутся только из входных данных: чего там нет, Claude помечает «[уточнить: …]», а не досочиняет;
- уверенность автора сохраняется: «думаю, успеем» не становится «успеваем»;
- вместо абстракции — что случится на деле и с кем;
- в тексте только нынешнее состояние: без истории правок и хешей коммитов;
- без внутреннего устройства: имя класса или функции остаётся, только если читатель его увидит или по нему что-то решит;
- одна мысль — одно предложение, по-русски, без кальки;
- перед выдачей Claude проверяет каждую строку: правда ли, нужна ли, поймёт ли её новый читатель.

## Как подключить

Промт подключают постоянным правилом или навыком, одним из двух.
- Правило лежит в каждом разговоре целиком, и Claude применяет его всегда.
- От навыка в каждом разговоре лежит только описание в пару строк. Сам промт Claude загружает, когда задача совпала с описанием: статус, тикет, план, дизайн-док, описание PR, рабочее письмо, сообщение коллеге или просьба переписать по-человечески. На поздравления, тосты, личные посты, перевод и код навык не загружается.
- Иногда Claude не загружает навык, хотя тот нужен, например на короткое сообщение коллеге. Тогда вызовите навык явно, как сказано ниже.

Ставить и правило, и навык незачем: навык повторит правило, которое уже действует.

**Навык через npx skills.** Команда [`npx skills`](https://github.com/vercel-labs/skills) ставит навык из этого репозитория в Claude Code, Codex, Cursor и другие агенты. Для неё нужен Node.js.

```bash
npx skills add anton-vinogradov/human-writing -g
```

- Команда сама находит агентов на компьютере. Если агентов несколько, она спросит, в каких из них поставить навык.
- Флаг `-g` ставит навык для всех проектов на компьютере. Без флага команда спросит, ставить навык в текущий проект или для всех проектов.
- Чтобы поставить навык только в Claude Code и без вопросов, добавьте `-a claude-code -y`.
- Новую версию навыка из репозитория ставит `npx skills update human-writing`.

**Навык в Claude Code без Node.js.** Навык ставится одной командой и доступен во всех проектах на этом компьютере:

```bash
mkdir -p ~/.claude/skills/human-writing && curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/skills/human-writing/SKILL.md -o ~/.claude/skills/human-writing/SKILL.md
```

Если Claude Code уже открыт, перезапустите его после установки навыка: папку навыков, которой не было при запуске, он не видит.
Чтобы Claude Code точно загрузил навык, начните сообщение с `/human-writing`, например: `/human-writing перепиши статус ниже`.

**Правило в Claude Code.** Добавьте промт в конец `~/.claude/CLAUDE.md`, и он будет действовать во всех проектах:

```bash
{ echo; curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/prompt.md; } >> ~/.claude/CLAUDE.md
```

**Правило в claude.ai и Claude Desktop.** Вставьте текст [`prompt.md`](prompt.md) в личные предпочтения в настройках claude.ai, и правило будет действовать во всех чатах. Для одного проекта вставьте его в инструкции проекта.

**Навык в claude.ai.** Навыки в claude.ai работают, только если включено выполнение кода. В тарифах Free, Pro и Max это пункт Code execution and file creation в Settings → Capabilities. В тарифах Team и Enterprise выполнение кода и навыки включает владелец организации: Organization settings → Plugins & skills, вкладка Policy.

Навык загружают ZIP-архивом. В корне архива должна лежать папка `human-writing` с файлом `SKILL.md`, иначе claude.ai не примет архив. На macOS и Linux архив собирает команда:

```bash
mkdir -p human-writing && curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/skills/human-writing/SKILL.md -o human-writing/SKILL.md && zip -r human-writing.zip human-writing
```

В Windows архив собирают три команды в PowerShell или cmd:

```powershell
mkdir human-writing
curl.exe -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/skills/human-writing/SKILL.md -o human-writing\SKILL.md
tar.exe -a -cf human-writing.zip human-writing
```

Загрузите архив: Customize → Skills → «+» → Create skill → Upload a skill. После загрузки проверьте, что переключатель навыка в Customize → Skills включён. Если Claude не загрузил навык сам, напишите в запросе «используй навык human-writing».

Если вы входите в Claude Code тем же аккаунтом claude.ai, навык из claude.ai появится и там, и ставить его командой не нужно. Для этого нужен Claude Code 2.1.273 или новее.

**Одним сообщением.** Вставьте промт в чат. Промт велит Claude сохранить его в постоянные инструкции, и Claude Code может сделать это сам. В чате без постоянной памяти правило действует до конца разговора.

## Как пользоваться

- Правило работает само: планы, тикеты, статусы и документы Claude сразу пишет в этом стиле.
- Чтобы переписать готовый текст, напишите «перепиши по-человечески» или «переведи на человеческий».
- Пометка «[уточнить: …]» стоит там, где во входных данных не было факта. Ответьте на неё или впишите факт сами перед отправкой.
- Если входные данные скудные, пометок будет много. Это честнее, чем правдоподобная выдумка.
- Большой документ не переписывайте целиком сразу: сначала попросите переписать один раздел и посмотрите результат.

## Пример

Руководитель спросил в чате: «как там миграция бэкапов, успеваем к концу месяца?» Все имена и факты в примере вымышленные.

**Было.** Черновик ответа:

> Привет! По миграции бэкапов: мы сначала хотели делать через rsync, потом Петя посмотрел и оказалось, что там проблема с hardlink'ами, поэтому переключились на restic, настроили его на трёх из пяти серверов (db-1, db-2, db-3), на db-4 пока ждём, когда админы откроют порт 8000 до MinIO, заявка висит с понедельника, а db-5 вообще под вопросом, потому что его, возможно, выводят из эксплуатации в октябре, но это не точно. Восстановление проверили на db-1, заняло 40 минут на 200 ГБ, что в целом ок, хотя хотелось бы быстрее. Старые бэкапы на NFS пока не удаляем, чтобы было куда откатиться. В целом думаю к концу месяца закончим, если с портом решится.

**Стало.** Тот же ответ, который Claude переписал по этому промту:

> Думаю, к концу месяца закончим, если админы откроют порт для db-4. [уточнить: к какому числу нужен открытый порт, чтобы успеть]
>
> - db-1, db-2, db-3: новые бэкапы настроены. Восстановление проверили на db-1: 200 ГБ восстановились за 40 минут, это приемлемо.
> - db-4: ждём, когда админы откроют порт 8000 до хранилища MinIO. Заявка висит с понедельника. [уточнить: номер заявки]
> - db-5: сервер, возможно, выведут из эксплуатации в октябре, но это не точно. [уточнить: переносим ли бэкапы db-5, пока нет решения о выводе]
>
> Старые бэкапы на NFS не удаляем. Если из новых бэкапов восстановиться не получится, мы вернёмся к старым. [уточнить: когда удаляем старые бэкапы]

Что изменилось:
- первая фраза отвечает на вопрос руководителя, а «думаю» осталось «думаю»;
- ушли история с rsync и hardlink'ами и название restic: на ответ руководителю они не влияют;
- все серверы и числа на месте: db-1…db-5, порт 8000, 200 ГБ за 40 минут, октябрь;
- чего в черновике не было, Claude не досочинил, а спросил пометкой.

Ещё два примера — раздел дизайн-документа и пункт плана — в [`examples.md`](examples.md).

## Как проверено

Claude, который знал только этот промт, переписал три плохих текста: пункт плана, раздел дизайн-документа и статус руководителю. Пункт плана он переписал дважды, независимо друг от друга, — всего четыре прогона.
- Отдельный проверяющий сверил результаты и критичных ошибок не нашёл.
- В одном прогоне из четырёх Claude подал догадку утверждением, а не вопросом. Поэтому готовый текст стоит перечитать перед отправкой.
- Примеры в этом репозитории — выход этой версии промта без правок руками.

Навык проверили отдельно. В навыке тот же промт, что в `prompt.md`, но без строки, которая просит сохранить правило в постоянные инструкции: навык и так установлен.
Загружает ли Claude навык сам, проверили на 40 просьбах: 20 рабочих текстов и 20 похожих нерабочих, например тост «по-человечески», перевод на английский и commit message. Каждую просьбу прогнали по 3–6 раз на каждой из двух моделей, Claude Opus 5.5 и Claude Sonnet 5, в Claude Code без личных настроек, MCP-серверов и других установленных навыков.
- На рабочих текстах Claude загрузил навык в 193 прогонах из 210.
- Хуже всего навык загружался на короткое сообщение коллеге в слаке (в 4 прогонах из 12), на «переведи на человеческий» (8 из 12) и на пункты для ретро (9 из 12).
- На нерабочих просьбах Claude не загрузил навык ни разу из 210 прогонов.
- Загрузку архива в claude.ai не проверяли.
