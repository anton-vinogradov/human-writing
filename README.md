# Промт «Пиши по-человечески»

Навык для Claude Code, Codex, Cursor и других агентов ставит одна команда:

```bash
npx skills add anton-vinogradov/human-writing -g
```

В чат любой нейросети достаточно вставить текст [`prompt.md`](https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/prompt.md). Остальные способы — в разделе [«Как подключить»](#как-подключить).

Для [автообновления при использовании](#автообновление) нужна отдельная установка через Git. Обновления включаются один раз для выбранной установки.

## Что не так

Нейросети пишут рабочие тексты так, что их трудно читать:
- в пункте плана вместо того, что появится, — имена классов, коммиты и тесты в скобках внутри скобок;
- в документе — история: «сначала делали так, потом выяснилось, теперь так»;
- вместо последствия — абстракция: «повышает надёжность», «обеспечивает гарантии»;
- канцелярит и калька с английского: «имплементирует подписку», «адресовать замечания»;
- где во входных данных нет факта, нейросети вставляют правдоподобную догадку, и читатель принимает её за факт.

Такой текст приходится переписывать руками или переспрашивать автора.

## Что предлагается

Промт в файле [`prompt.md`](prompt.md), около 1 400 слов. Промт написан по-английски, а текст нейросеть пишет на языке читателя: русский черновик переписывает по-русски, английский — по-английски. Если подключить промт постоянным правилом, нейросеть применяет его ко всем рабочим текстам без напоминаний. В промте нет ничего, что работает только в Claude.
Те же правила письма лежат в [`skills/human-writing/SKILL.md`](skills/human-writing/SKILL.md) навыком (skill). Навык агент загружает сам, когда видит подходящую задачу. В навыке также есть инструкция проверки обновлений.

Что он требует от нейросети:
- первая фраза несёт главную мысль;
- каждая часть текста отвечает на один вопрос;
- нейросеть берёт факты только из входных данных и не досочиняет. Где факта нет, она ставит пометку «[уточнить: …]», а в английском тексте — «[clarify: …]»;
- уверенность автора сохраняется: «думаю, успеем» не становится «успеваем»;
- вместо абстракции — что случится на деле и с кем;
- в тексте только нынешнее состояние: без истории правок и хешей коммитов;
- без внутреннего устройства: имя класса или функции остаётся, только если читатель его увидит или по нему что-то решит;
- одна мысль — одно предложение, без канцелярита и кальки;
- простые слова, без идиом и сленга, чтобы текст понял и читатель, для которого язык не родной;
- перед выдачей нейросеть проверяет, можно ли выполнить задачу по тексту целиком, затем проверяет каждую строку: правда ли, нужна ли, понятна ли.

## Как подключить

Промт подключают постоянным правилом или навыком, одним из двух.
- Правило лежит в каждом разговоре целиком, и нейросеть применяет его всегда.
- От навыка в каждом разговоре лежит только описание в пару строк. Сам промт агент загружает, когда задача совпала с описанием: статус, тикет, план, дизайн-док, описание PR, рабочее письмо, сообщение коллеге или просьба переписать по-человечески. Поздравления, тосты, личные посты, перевод и код описание навыка исключает.
- Иногда агент не загружает навык, хотя тот нужен: Claude, например, пропускал его на коротком сообщении коллеге. Тогда вызовите навык явно, как сказано ниже.

Ставить и правило, и навык незачем: навык повторит правило, которое уже действует.

### Любая нейросеть: одним сообщением

Откройте [`prompt.md` простым текстом](https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/prompt.md), скопируйте его целиком и отправьте в чат первым сообщением. Так промт можно дать ChatGPT, Gemini, DeepSeek и любой другой нейросети.
Промт велит нейросети сохранить его в постоянные инструкции, и Claude Code может сделать это сам. В чате без постоянной памяти правило действует до конца разговора.

### Агенты: Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot

**Навык через npx skills.** Команда [`npx skills`](https://github.com/vercel-labs/skills) ставит навык из этого репозитория в Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot и другие агенты. Для неё нужен Node.js.

```bash
npx skills add anton-vinogradov/human-writing -g
```

- Команда сама находит агентов на компьютере. Если агентов несколько, она спросит, в каких из них поставить навык.
- Флаг `-g` ставит навык для всех проектов на компьютере. Без флага команда спросит, ставить навык в текущий проект или для всех проектов.
- Чтобы поставить навык без вопросов, назовите агентов флагами `-a` и добавьте `-y`, например `-a claude-code -a codex -y`. Имена агентов для `-a` перечислены в [таблице npx skills](https://github.com/vercel-labs/skills#supported-agents).
- Новую версию навыка из репозитория ставит `npx skills update human-writing`.

**Навык без Node.js.** Claude Code читает навыки из папки `~/.claude/skills`, а Codex, Cursor, Gemini CLI и GitHub Copilot — из `~/.agents/skills`. Обе папки общие для всех проектов на компьютере. Навык для Claude Code ставит команда:

```bash
mkdir -p ~/.claude/skills/human-writing && curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/skills/human-writing/SKILL.md -o ~/.claude/skills/human-writing/SKILL.md
```

Навык для Codex, Cursor, Gemini CLI и GitHub Copilot ставит команда:

```bash
mkdir -p ~/.agents/skills/human-writing && curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/skills/human-writing/SKILL.md -o ~/.agents/skills/human-writing/SKILL.md
```

После установки навыка:
- **Claude Code** не видит папку навыков, которой не было при его запуске: если он уже открыт, перезапустите его. Чтобы Claude Code точно загрузил навык, начните сообщение с `/human-writing`, например: `/human-writing перепиши статус ниже`.
- **Codex** замечает новый навык сам, а если не заметил, перезапустите его. Чтобы вызвать навык явно, упомяните его в сообщении: `$human-writing перепиши статус ниже`.
- **Cursor** ищет навыки при запуске: перезапустите его. Чтобы вызвать навык явно, начните сообщение с `/human-writing`.
- **Gemini CLI** перечитывает навыки по команде `/skills reload`.

**Правило в агентах.** Агент читает постоянные инструкции из своего файла в начале разговора, поэтому правило действует с нового разговора. Файлы ниже общие для всех проектов, а команды дописывают промт в конец файла.

Claude Code:

```bash
{ echo; curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/prompt.md; } >> ~/.claude/CLAUDE.md
```

Codex:

```bash
{ echo; curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/prompt.md; } >> ~/.codex/AGENTS.md
```

Codex читает из всех файлов AGENTS.md вместе не больше 32 КиБ, промт занимает из них 7 КиБ. Лимит поднимает параметр `project_doc_max_bytes` в `~/.codex/config.toml`.

Gemini CLI:

```bash
{ echo; curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/prompt.md; } >> ~/.gemini/GEMINI.md
```

GitHub Copilot CLI:

```bash
{ echo; curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/prompt.md; } >> ~/.copilot/copilot-instructions.md
```

В Cursor правило вставляют текстом в User Rules: Customize → Rules. В старых версиях Cursor этот раздел лежит в Cursor Settings → Rules.

### claude.ai и Claude Desktop

**Правило.** Вставьте текст [`prompt.md`](prompt.md) в личные предпочтения в настройках claude.ai, и правило будет действовать во всех чатах. Для одного проекта вставьте его в инструкции проекта.

**Навык.** Навыки в claude.ai работают, только если включено выполнение кода. В тарифах Free, Pro и Max это пункт Code execution and file creation в Settings → Capabilities. В тарифах Team и Enterprise выполнение кода и навыки включает владелец организации: Organization settings → Plugins & skills, вкладка Policy.

Навык загружают ZIP-архивом. В корне архива должна лежать папка `human-writing` с файлом `SKILL.md`, иначе claude.ai не примет архив. На macOS и Linux архив собирает команда:

```bash
mkdir -p human-writing && curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/skills/human-writing/SKILL.md -o human-writing/SKILL.md && zip -r human-writing.zip human-writing
```

В Windows архив собирают три команды в PowerShell или cmd:

```powershell
mkdir human-writing
curl.exe -fsSL https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/skills/human-writing/SKILL.md -o human-writing\SKILL.md
tar.exe -a -cf human-writing.zip human-writing
```

Загрузите архив: Customize → Skills → «+» → Create skill → Upload a skill. После загрузки проверьте, что переключатель навыка в Customize → Skills включён. Если Claude не загрузил навык сам, напишите в запросе «используй навык human-writing».

Если вы входите в Claude Code тем же аккаунтом claude.ai, навык из claude.ai появится и там, и ставить его командой не нужно. Для этого нужен Claude Code 2.1.273 или новее.

### ChatGPT

Вставьте текст [`prompt.md`](prompt.md) в инструкции проекта: меню проекта ••• → Project settings. Правило будет действовать во всех чатах этого проекта.
В Custom instructions в настройках промт не помещается. Это поле вмещает 5 000 знаков на платных тарифах и 1 500 на бесплатном, а в промте 6 820 знаков.

### Gemini

В чат Gemini навык загружают файлом `SKILL.md`. Сохраните [файл навыка](https://raw.githubusercontent.com/anton-vinogradov/human-writing/main/skills/human-writing/SKILL.md) и загрузите его по [инструкции Google](https://support.google.com/gemini/answer/17094296).

## Автообновление

При использовании навыка агент запускает проверку обновлений. Скрипт обращается к этому репозиторию не чаще раза в сутки, включая неудачные попытки. После обновления агент перечитывает навык и применяет его в текущей задаче. Фонового процесса нет: проверка зависит от того, загрузил ли агент навык и может ли выполнить команду.

Нужны Git, Python 3.9 или новее, доступ к сети и право изменять установку. Правила письма работают и без них. В обычных копиях, включая установки через `npx skills`, отдельный `SKILL.md` и ZIP, этот механизм обновлений не работает. Постоянные инструкции из `prompt.md` он тоже не обновляет.

### Установка с автообновлением

Сохраните весь репозиторий отдельно от рабочих проектов и папок обнаружения навыков. В папке навыков создайте ссылку на `skills/human-writing` внутри клона. Так агент видит навык, а скрипт может обновлять его Git-клон целиком.

Если навык уже установлен, сначала сохраните его папку вне всех папок обнаружения навыков. Сравните личные правки с версией в репозитории и сохраните резервную копию. Перенос личных правок в новую установку приостановит её автообновление. Оставьте одну доступную агенту установку `human-writing`.

Для macOS и Linux, если агент читает `~/.agents/skills`:

```sh
test ! -e "$HOME/.agents/skills/human-writing" &&
test ! -L "$HOME/.agents/skills/human-writing" &&
mkdir -p "$HOME/.local/share/agent-skills" "$HOME/.agents/skills" &&
git clone --branch main https://github.com/anton-vinogradov/human-writing.git "$HOME/.local/share/agent-skills/human-writing" &&
ln -s "$HOME/.local/share/agent-skills/human-writing/skills/human-writing" "$HOME/.agents/skills/human-writing"
```

Проверки перед созданием ссылки сохраняют существующую установку. Если путь занят, сначала выполните перенос в резервную копию. Для другого каталога навыков замените `~/.agents/skills` на путь, который использует ваш агент. На Windows клонируйте репозиторий отдельно и создайте ссылку на вложенную папку навыка средствами вашей среды.

Автообновление выключено до явного включения:

```sh
python3 "$HOME/.agents/skills/human-writing/scripts/update.py" --enable
```

На Windows при необходимости замените `python3` на `py -3`. Во всех командах используйте фактический путь установки. Скрипт должен сообщить `enabled`: это подтверждает сохранение настройки.

Включение разрешает применять будущие коммиты ветки `main` этого репозитория, включая сам скрипт обновления. Разрешение относится только к отдельному клону навыка. Оно не разрешает менять рабочие проекты или постоянные инструкции агента.

### Проверка и отключение

Для проверки сейчас, не дожидаясь следующего суточного интервала:

```sh
python3 "$HOME/.agents/skills/human-writing/scripts/update.py" --force
```

Для отключения:

```sh
python3 "$HOME/.agents/skills/human-writing/scripts/update.py" --disable
```

`--force` отменяет только ожидание следующей проверки. Он не включает обновления и не обходит защиту личных правок.

- Скрипт сохраняет локальные правки, дополнительные файлы, в том числе игнорируемые Git, и собственные коммиты. Если они мешают обновлению, он пропускает его.
- Скрипт обновляет только клон этого репозитория на ветке `main`. Он применяет новую версию без объединения расходящихся веток и без сброса файлов.
- При отсутствии сети, инструментов или прав, а также при занятой установке работа продолжается с установленным навыком. Каждая команда Git ограничена 15 секундами.
- Настройка, время последней попытки и блокировка хранятся в `.git` клона. Одновременные вызовы не обновляют установку параллельно.

После `updated` агент должен перечитать `SKILL.md`. При `skipped` причина указана в результате; существующие файлы остаются доступными. Старые копии сами не получат скрипт: для перехода на автообновление выполните установку выше.

## Как пользоваться

- Правило работает само: планы, тикеты, статусы и документы нейросеть сразу пишет в этом стиле.
- Чтобы переписать готовый текст, напишите «перепиши по-человечески» или «переведи на человеческий».
- Пометка «[уточнить: …]» стоит там, где во входных данных не было факта. Ответьте на неё или впишите факт сами перед отправкой.
- Если входные данные скудные, пометок будет много. Это честнее, чем правдоподобная выдумка.
- Большой документ не переписывайте целиком сразу: сначала попросите переписать один раздел и посмотрите результат.

## Пример

Руководитель спросил в чате: «как там миграция бэкапов, успеваем к концу месяца?» Все имена и факты в примере вымышленные.

**Было.** Черновик ответа:

> Привет! По миграции бэкапов: мы сначала хотели делать через rsync, потом Петя посмотрел и оказалось, что там проблема с hardlink'ами, поэтому переключились на restic, настроили его на трёх из пяти серверов (db-1, db-2, db-3), на db-4 пока ждём, когда админы откроют порт 8000 до MinIO, заявка висит с понедельника, а db-5 вообще под вопросом, потому что его, возможно, выводят из эксплуатации в октябре, но это не точно. Восстановление проверили на db-1, заняло 40 минут на 200 ГБ, что в целом ок, хотя хотелось бы быстрее. Старые бэкапы на NFS пока не удаляем, чтобы было куда откатиться. В целом думаю к концу месяца закончим, если с портом решится.

**Стало.** Тот же ответ, который Claude переписал по этому промту:

> Привет! Думаю, к концу месяца закончим, если админы откроют порт для db-4.
>
> Бэкапы переносим на restic:
> - db-1, db-2, db-3: restic настроен.
> - db-4: ждём, когда админы откроют порт 8000 до MinIO. Заявка открыта с понедельника.
> - db-5: под вопросом. Его могут вывести из эксплуатации в октябре, но это не точно. [уточнить: успеем ли перенести бэкапы db-5 к концу месяца, если его не выведут из эксплуатации]
>
> Мы проверили восстановление на db-1: 200 ГБ восстановили за 40 минут. Это приемлемо, но хотелось бы быстрее.
>
> Старые бэкапы на NFS пока не удаляем. Если с новыми бэкапами будет проблема, мы восстановим данные из старых.

Что изменилось:
- первая строка отвечает на вопрос руководителя, а «думаю» осталось «думаю»;
- ушла история с rsync, hardlink'ами и Петей: на ответ руководителю она не влияет;
- все серверы и числа на месте: db-1…db-5, порт 8000, 200 ГБ за 40 минут, октябрь;
- чего в черновике не было, Claude не досочинил, а спросил пометкой: успеем ли перенести бэкапы db-5, если сервер оставят.

Ещё три примера — раздел дизайн-документа, пункт плана и описание PR на английском — в [`examples.md`](examples.md).

## Как проверено

Claude Opus 5.5, который знал только этот промт, переписал три плохих русских текста: пункт плана, раздел дизайн-документа и статус руководителю. Ещё он переписал одно описание PR на английском. Пункт плана он переписал дважды, независимо друг от друга. Всего вышло пять прогонов.
- Все русские тексты Claude написал по-русски с пометками «[уточнить: …]», а описание PR — по-английски с пометками «[clarify: …]».
- Отдельный проверяющий сверил каждый результат со входом. В четырёх прогонах из пяти он не нашёл критичных ошибок.
- В одном прогоне пункта плана Claude подал догадку утверждением, а не вопросом, и досочинил шаг сценария. Поэтому готовый текст стоит перечитать перед отправкой.
- Примеры в этом репозитории — выход этой версии промта без правок руками.

Навык проверили отдельно. В навыке те же правила письма, что в `prompt.md`, но без строки, которая просит сохранить правило в постоянные инструкции: навык и так установлен. Раздел обновления относится только к установленному навыку.
Загружает ли Claude навык сам, проверили на описании навыка с тем же смыслом, но написанном по-русски. С английским описанием замер не повторяли. Проверили на 40 просьбах: 20 рабочих текстов и 20 похожих нерабочих, например тост «по-человечески», перевод на английский и commit message. Каждую просьбу прогнали по 3–6 раз на каждой из двух моделей: Claude Opus 5.5 и Claude Sonnet 5. Прогоны шли в Claude Code без личных настроек, MCP-серверов и других установленных навыков.
- На рабочих текстах Claude загрузил навык в 193 прогонах из 210.
- Хуже всего навык загружался на короткое сообщение коллеге в слаке (в 4 прогонах из 12), на «переведи на человеческий» (8 из 12) и на пункты для ретро (9 из 12).
- На нерабочих просьбах Claude не загрузил навык ни разу из 210 прогонов.
- Загрузку архива в claude.ai не проверяли.

Подключение в других нейросетях проверили частично.
- `npx skills` 1.7.0 ставит навык из этого репозитория: для Claude Code в `~/.claude/skills/human-writing`, для Codex в `~/.agents/skills/human-writing`. Команда `npx skills update human-writing` ставит новую версию.
- Codex 0.160.1 видит навык из `~/.agents/skills` и правило из `~/.codex/AGENTS.md`: оба попадают в то, что Codex передаёт модели. Это показывает команда `codex debug prompt-input`.
- Пути и пункты меню Cursor, Gemini CLI, GitHub Copilot, ChatGPT и Gemini взяты из их документации, руками их не проверяли.
- В Codex отдельно проверили чтение эксплуатационной инструкции целиком: два независимых проверяющих получили разные версии текста без кода и истории обсуждения. Они обнаружили недостающие шаги проверки успеха и восстановления. После дополнения текста повторная проверка нашла ответы на все вопросы процедуры. Это проверка одного документа, а не общая оценка качества письма модели.

Тесты скрипта обновления работают без сети, на временных Git-репозиториях. Они прошли на macOS; Windows и Linux не проверялись. Запуск из корня этого репозитория:

python3 -B -m unittest discover -s tests -v
